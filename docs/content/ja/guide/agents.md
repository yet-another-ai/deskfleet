# エージェントと共同作業

## 使い慣れたエージェントを使う

DeskFleet は、Codex CLI、Claude Code、Cursor CLI、Grok CLI、DeepSeek Harness、その他の ACP 対応実行ファイルに接続します。作業を実行するマシンの **設定 → エージェント** で構成してください。

エージェントの追加時に CLI を選ぶと、DeskFleet が選択したマシン上でその CLI を確認します。状態には **準備完了**、**未ログイン**、**未インストール** などが表示されます。組み込み対応の CLI が見つからない場合は、**インストール** から公式インストーラーを実行できます。ダイアログには実行中の出力が表示され、完了すると実行ファイルのパスが設定されます。インストールできるかどうかは、対象マシンの OS によって異なります。特定の実行ファイルや環境変数を指定するには、**詳細設定** を開いてください。

**ログイン** を選び、ログイン用ターミナルに表示される認証リンクや案内に従って認証します。**接続をテスト** は、ログイン処理を開始せずに、現在の設定と認証情報を確認します。テストに失敗した場合は、**詳細** でエージェントの出力全体を確認できます。CLI がログイン状態を報告できない場合は、**準備完了** の代わりに **インストール済み** と表示されます。これは未ログインを意味するものではありません。

新しいセッションでは、ひとつのプロバイダーを選択します。利用できるモデル設定、推論オプション、実行中の指示追加、会話の再開は、そのプロバイダーの対応状況によって異なります。

## セッションを共有する

権限を持つチームメンバーは、複数のクライアントから同じセッションを操作できます。それぞれが会話を読み、キューに入力を追加し、共有された権限要求に回答できます。メッセージには送信者が記録され、権限要求への回答は全員に反映されます。

エージェントが対応している場合、**今すぐ指示を追加** を使うと、現在のターンに修正指示を送れます。対応していない場合は、後続の作業用にリクエストをキューに追加してください。

## 作業場所を選ぶ

ワークスペースには、ひとつのマシン上にある、ひとつ以上の既存ディレクトリを登録します。最初のディレクトリがデフォルトの作業ディレクトリになります。

- **新しいワークツリー** は、コミット済みの HEAD から独立した Git チェックアウトを作成します。未コミットの変更はコピーされません。
- **作業ディレクトリ** は、既存のディレクトリとその中のファイルを、未コミットの変更も含めてそのまま使用します。

ワークツリーは作業コピーを分離しますが、エージェントによるコンピューターへのアクセスをサンドボックス化するものではありません。

## 作業を確認し、続ける

会話とともに、ツールの実行状況を確認できます。変更パネルを開くとファイルの差分を確認でき、セッションのターミナルを開くと同じディレクトリで作業できます。

ページを離れたりデスクトップウィンドウを閉じたりしても、マシンとデーモンが動作している間はエージェントも動作を続けます。デスクトップアプリを終了すると、そのアプリ内で動くデーモンも停止します。同期済みの会話履歴は、マシンがオフラインでも読むことができます。

セッションをアーカイブすると、実行中のプロセスが停止し、会話、ワークツリーのファイル、キュー内の入力、ターミナルの記録は保持されます。復元すると、セッションを再び利用できます。その後にメッセージを送ると、プロバイダーの対応状況に応じて起動または再開します。
